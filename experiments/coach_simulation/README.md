# 提示「內容」的模擬實驗

> 這個資料夾補的是 `experiments/learner_simulation.cpp` **沒有**回答的問題。
> 兩者不是取代關係。

---

## 跟 learner_simulation.cpp 的分工

| | `learner_simulation.cpp` | 這裡 |
|---|---|---|
| 驗證什麼 | **時序** —— 門檻會不會太早或太晚 | **內容** —— 三層提示各自傳遞了什麼 |
| 學習者能力 | `base_skill` 機率 + `hint_boost[3]` | **已知概念的集合** |
| 成敗如何決定 | 擲骰子 | **窮舉已知概念涵蓋得到的走法** |
| 對應系統 | `CoachCampaign` 六關卡 | `CognitiveHintEngine` 三層提示 |

**關鍵差別在「能力」怎麼表示。**

C++ 版把能力寫成機率，所以 `hint_boost[POINT] = 0.55` 這一行
**已經假設了「指方向」有用**，只是不知道有多少用。

知識模型不設這個參數。它問的是：一個不知道「牌可以接在 Run 前面」的人，
被告知「留意紅色那排」之後，**他的搜尋空間有沒有改變？**

答案是沒有 —— 他知道要看哪裡，但不知道要拿那排做什麼。

**這個發現在機率模型裡測不出來**，因為機率模型從一開始就假設了提示有效。

---

## 三個發現

### 一、前兩層提示對缺乏概念的學習者，效果是零

| 起點 | 靠「輕推」解出 | 靠「指方向」解出 | 差異 |
|---|---|---|---|
| 完全不會 | 0 / 60 | 0 / 60 | **+0** |
| 只認得 Run/Group | 0 / 60 | 0 / 60 | **+0** |
| 會接尾巴 | 29 / 60 | 29 / 60 | **+0** |
| 只差 Joker | 47 / 60 | 47 / 60 | **+0** |

複驗 40 次（10 組題目 × 4 種起點），差異最小 0、最大 0。

**這不是統計上的接近，是結構上的必然。**
這兩層傳遞的是位置資訊，學習者缺的是概念資訊。

### 二、把中間層換成「教概念」，全面變好

| 設計 | 自主率（10 組題目） | 標準差 |
|---|---|---|
| 位置型（現行） | 85.8% | 0.016 |
| 概念型 | 95.0% | 0.008 |
| **精簡概念型（拿掉輕推）** | **96.3%** | 0.010 |

概念型與精簡型在 10 組題目上**全部贏過位置型，10/10**。

**移除一層提示，效果反而最好** ——
輕推那層不傳遞資訊，唯一作用是延後真正有用的提示。

越弱的學習者改善越大（完全不會 +11%、只認得 Run/Group +14%，
但「只差 Joker」只有 +3%）。目標族群正是最左邊那兩欄。

### 三、門檻不是關鍵參數

概念型設計下，門檻從 1/2 掃到 3/6，自主率都在 91%~94%。

**提示的內容比時機重要。**

## 這對六關卡設計的直接意涵

`coach_campaign.h` 裡，**L6 的 `max_tier` 只到 `GENTLE_NUDGE`**。

而 `learner_simulation.cpp` 跑出來的結果是：
L6 的完全新手平均連續卡 **16 回合** —— 這是保底機制存在的理由。

把兩邊放在一起看：

> 如果「輕推」對能力不足者不傳遞任何資訊，
> 那 L6 的 16 回合卡關就不是意外，是必然。
> **保底機制是在補這個洞，但根因可能是「輕推」這一層本身就無效。**

**這是可以直接驗證的假說：**
把 L6 的 `max_tier` 換成傳遞概念的提示（而非位置提示），
看 `longest_stuck` 會不會掉、`safety_net_turns` 會不會變少。

如果會，那保底機制可以縮減，因為它補的洞被堵住了。

## 難度分級與舉一反三

| 級別 | 每次曝光增益 | 家族遷移 |
|---|---|---|
| easy | 0.50（看兩次會） | 0.25 |
| hard | 0.20（看五次會） | 0.05 |

熟悉度曲線把八個概念分成三群：

```
RUN_BASIC        [easy] 1.00 ████████████████████████
GROUP_BASIC      [easy] 1.00 ████████████████████████
ATTACH_TAIL      [easy] 1.00 ████████████████████████
GROUP_COMPLETE   [easy] 1.00 ████████████████████████
JOKER_AS_TILE    [hard] 1.00 ████████████████████████
RUN_LONG         [hard] 1.00 ████████████████████████
ATTACH_HEAD      [hard] 0.84 ████████████████████
JOKER_FILL_GAP   [hard] 0.49 ███████████
```

`JOKER_FILL_GAP` 是唯一沒學會的 —— hard、家族只有兩個成員所以
舉一反三沾不到光、還要先會 `JOKER_AS_TILE`。

**這正好對應 `CognitiveHintEngine` 刻意保留的限制**
（Joker 只填內部缺口、不往兩端延伸），
也對應 `coach_campaign.h` 裡 L3 就要教 `JOKER_FILL` 這個排序。

最難學的概念，被排在第三關。

## 做了但沒用的：鷹架淡出

實作了「兩難時降低提示層級」——
學習者已經想得到多個走法時，不要幫他選。

**四種起點全部 +0%。**

原因：概念型提示下自主率本來就 94%，
學習者幾乎走不到需要降級的情境 —— 鷹架早就撤掉了，沒有東西可以再撤。

它解決的是「過度依賴」，但概念型提示本來就不製造依賴。

留著這個記錄，因為做了才知道不需要，比沒做過就說不需要有力。

## 誠實標註的範圍

**這是模擬，不是使用者測試。** 從來沒有真人測過。

複驗只證明：**在這個學習者模型底下，結論對題目分布不敏感。**
它沒有證明模型像真人 —— 10 組題目換來換去，模型的假設從頭到尾沒變過。
「教概念之後馬上能用」、「曝光 0.34 累積三次會」這些數字仍然是設定的，
不是量出來的。

正確的說法是：

> 在「學習者的能力受限於概念而非運氣」這個假設下，
> 概念型提示優於位置型，且此結論對題目分布穩健。

前提本身仍需真人驗證 —— 這跟 `learner_simulation.cpp` 註解裡
寫的「本實驗無法回答真人是否會因此學得更好」是同一個限制。

其他限制：

- 題目每題只考一個概念，所以學習曲線 30 題就平了。
  真實局面會需要多概念組合，這部分還沒做 ——
  而 `CoachCampaign` 的 L5（大風吹）正是多概念組合的關卡
- 「兩難」的定義是「候選走法多於一個」，這是簡化
- 學習者不會遺忘。真人會，而且目標族群是認知退化的長輩

## 曾經寫過但刪掉的：機率模型版本

一開始寫了一支 `threshold_sensitivity.py`，用機率模型掃描門檻。

**寫完才發現它跟 `learner_simulation.cpp` 是同一個東西**，
而且 C++ 版做得更完整 —— 有關卡難度衰減、保底機制、
「太早給答案」與「卡死沒人救」兩種異常偵測，這些 Python 版都沒有。

刪掉了。重複造輪子沒有價值，記下來避免之後又做一次。

不過那次有個值得記的錯誤：第一版忘了加「玩家會放棄」的機制，
結論跑出來是「**最好的教練是完全不給提示**」，自主率 94~100%。

荒謬得很明顯，但它指出了模型缺什麼 ——
設計文件裡早就寫過「卡住太久人就放棄了」，少了這個，教練就沒有存在的必要。
