# 認知教練 · 提示設計模擬實驗

驗證 `CognitiveHintEngine` 的三層提示設計。

---

## 為什麼要做

`cognitive_hint_engine.cpp` 目前是：

```cpp
if (stuck_turns < 2) return GENTLE_NUDGE;
if (stuck_turns < 4) return POINT_TO_AREA;
return REVEAL_MOVE;
```

設計文件自己寫了：「示意性門檻，不是臨床驗證過的數字」。

問題是 —— **沒有真人數據，這兩個數字要怎麼定？**

---

## 方法上的兩次修正

### 第一版：機率模型（`threshold_sensitivity.py`）

把學習者寫成「有 P 的機率找到解」，P 是手調的數字。

**問題：循環論證。** 用自己編的參數，驗證自己編的門檻。

不過這一版留著，因為它記錄了一個有價值的錯誤 ——
第一次跑的時候結論是「**最好的教練是完全不給提示**」，
自主率 94~100%，荒謬得很明顯。

原因是模型裡的玩家可以無限嘗試、永遠不會挫折。
設計文件自己寫過：「但也不能不給提示，卡住太久人就放棄了。」
**少了放棄機制，教練就沒有存在的必要。**

加上之後張力才出現。

### 第二版：知識模型（`knowledge_learner.py`）

改成學習者持有一組「已知概念」，每回合窮舉所有它**想得到**的走法 ——
想得到的範圍由已知概念決定。

**能不能解出來是推導出來的，不是抽籤決定的。**
一個不知道 Group 的人，窮舉時根本不會產生 Group 的候選 ——
不是他運氣不好，是那個念頭不存在。

---

## 三個發現

### 一、前兩層提示對卡住的人效果是零

| 起點 | 靠「輕推」解出 | 靠「指方向」解出 | 差異 |
|---|---|---|---|
| 完全不會 | 0 / 60 | 0 / 60 | **+0** |
| 只認得 Run/Group | 0 / 60 | 0 / 60 | **+0** |
| 會接尾巴 | 29 / 60 | 29 / 60 | **+0** |
| 只差 Joker | 47 / 60 | 47 / 60 | **+0** |

複驗 40 次（10 組題目 × 4 種起點），**差異最小 0、最大 0**。

這不是統計上的接近，是結構上的必然：
這兩層傳遞的是**位置資訊**，學習者缺的是**概念資訊**。

跟一個不知道「牌可以接在 Run 前面」的人說「留意紅色那排」，
他知道要看哪裡，但不知道要拿那排做什麼。

### 二、把提示換成教概念，全面變好

| 設計 | 自主率（10 組題目） | 標準差 |
|---|---|---|
| 位置型（現行） | 85.8% | 0.016 |
| 概念型 | 95.0% | 0.008 |
| **精簡概念型（拿掉輕推）** | **96.3%** | 0.010 |

**概念型與精簡型在 10 組題目上全部贏過位置型，10/10，沒有例外。**

而且**移除一層提示，效果反而最好** ——
輕推那層不傳遞資訊，唯一作用是延後真正有用的提示。

越弱的學習者改善越大：

| 起點 | 位置型 | 概念型 | 差 |
|---|---|---|---|
| 完全不會 | 82% | 93% | **+11%** |
| 只認得 Run/Group | 82% | 96% | **+14%** |
| 會接尾巴 | 92% | 99% | +7% |
| 只差 Joker | 97% | 100% | +3% |

目標族群（長輩、新手）正是最左邊那兩欄。

### 三、門檻不是關鍵參數

概念型設計下，門檻從 1/2 掃到 3/6，自主率都在 91%~94%。

**一直在調的那個參數，可能不是該調的那個。提示的內容比時機重要。**

## 難度分級與舉一反三（`adaptive_coach.py`）

| 級別 | 每次曝光增益 | 家族遷移 |
|---|---|---|
| easy | 0.50（看兩次會） | 0.25 |
| hard | 0.20（看五次會） | 0.05 |

熟悉度曲線把八個概念分成三群：

```
RUN_BASIC        [easy] 1.00 ████████████████████████
GROUP_BASIC      [easy] 1.00 ████████████████████████
ATTACH_TAIL      [easy] 1.00 ████████████████████████
GROUP_COMPLETE   [easy] 1.00 ████████████████████████
JOKER_AS_TILE    [hard] 1.00 ████████████████████████
RUN_LONG         [hard] 1.00 ████████████████████████
ATTACH_HEAD      [hard] 0.84 ████████████████████
JOKER_FILL_GAP   [hard] 0.49 ███████████
```

`JOKER_FILL_GAP` 是唯一沒學會的，原因複合 ——
hard、家族只有兩個成員所以舉一反三沾不到光、還要先會 `JOKER_AS_TILE`。

**這正好對應 code 裡刻意保留的限制**（Joker 只填內部缺口、不往兩端延伸）。
最難學的概念，也是提示引擎覆蓋最少的那個。

---

## 做了但沒用的：鷹架淡出

實作了「兩難時降低提示層級」——
學習者已經想得到多個走法時，不要幫他選。

**結果四種起點全部 +0%。**

原因：概念型提示下自主率本來就 94%，
學習者幾乎走不到需要降級的情境 —— 鷹架早就撤掉了，沒有東西可以再撤。

它解決的是「過度依賴」，但概念型提示本來就不製造依賴。
**在位置型設計下可能有用，在概念型下是多餘的。**

留著這個記錄，因為做了才知道不需要，比沒做過就說不需要有力。

## 誠實標註的範圍

**這是模擬，不是使用者測試。** 從來沒有真人測過。

複驗只證明：**在這個學習者模型底下，結論對題目分布不敏感。**
它沒有證明模型像真人 —— 10 組題目換來換去，模型的假設從頭到尾沒變過。
「教概念之後馬上能用」、「曝光 0.34 累積三次會」這些數字仍然是設定的，
不是量出來的。

正確的說法是：

> 在「學習者的能力受限於概念而非運氣」這個假設下，
> 概念型提示優於位置型，且此結論對題目分布穩健。

前提本身仍需真人驗證。

其他限制：

- 題目每題只考一個概念，所以學習曲線 30 題就平了。
  真實局面會需要多概念組合，這部分還沒做
- 「兩難」的定義是「候選走法多於一個」，這是簡化
- 學習者不會遺忘。真人會，而且目標族群是認知退化的長輩 ——
  遺忘機制沒做，但它可能比提示系統更重要
