# Actor-Critic 實驗：學會拉密的一個子問題

## 起點

向成大蘇文鈺教授請教教練型 AI 的設計時，他指出這個結構類似 RL 裡的 Actor-Critic，
並提到他們在機器人應用上確實會用到類似的技巧。

這份文件記錄一個親手實作的驗證：**用 Actor-Critic 學會簡化版的拉密**。

不用 PyTorch，前向與反向傳播都手刻——因為這個網路只有幾百個參數，
手寫的話每一步梯度都看得見，呼叫 `loss.backward()` 學不到那些東西。

---

## 為什麼要簡化

完整拉密不適合當第一個 RL 題目，有三個結構性的原因：

| 問題 | 說明 |
|---|---|
| **動作空間巨大** | 一手可以出好幾組牌、還能重組桌面，可能的動作有數萬種。而 softmax 要對每個動作算機率。（對照：西洋棋約 35 種、圍棋 250 種） |
| **狀態是變長的** | 桌面組數不固定、每組張數不固定、手牌數會變。神經網路需要固定長度的輸入。 |
| **獎勵稀疏** | 只有贏了才有分，中間幾十手完全沒有訊號。 |

任何一件都足以讓訓練失敗。所以先做一個縮到最小、但保留核心決策的版本。

### 簡化後的題目

```
局面：桌面一條三張的 Run，手上五張牌
動作：出第 1~5 張，或抽牌（共 6 種）
目標：接得上就出，接不上就抽
```

**這個題目簡單到人一眼看得出正確答案——正因為如此，才能驗證 AI 是不是真的學會。**
如果連這個都學不會，放大到完整拉密只會更糟。

### 狀態表示（12 維）

| 維度 | 內容 |
|---|---|
| 0–1 | Run 的頭與尾（正規化到 0–1） |
| 2–6 | 五張手牌的數字 |
| 7–11 | 五張手牌「接不接得上」的旗標 |

最後五維是刻意加的：它等於把「這張接不接得上」直接告訴網路。
沒有它的話，網路要自己從數字關係學出「差 1 才接得上」，那是另一個學習問題。
**這是為了讓實驗聚焦而做的簡化，不是因為那樣比較好。**

## 架構

```
        狀態 (12 維)
             │
      ┌──────┴──────┐
      ▼             ▼
  ┌───────┐    ┌────────┐
  │ Actor │    │ Critic │
  │ 12→24 │    │ 12→24  │
  │ →6    │    │ →1     │
  └───┬───┘    └────┬───┘
      │             │
   動作機率      這個局面
   (softmax)     值多少分
      │             │
      └──────┬──────┘
             ▼
    advantage = 實際回報 − Critic 預期
             ▼
      Actor 依 advantage 更新
```

- Actor：462 個參數
- Critic：337 個參數

### 為什麼需要 Critic 這個「基準線」

如果直接用「實際回報」當訊號，在一個每步都能拿高分的局面裡，
**所有動作都會被鼓勵——包括不好的那些**。

Critic 提供「這個局面應該值多少」，讓訊號變成**相對好壞**而不是絕對分數。

### 梯度

softmax 加上 log 之後，梯度有一個異常簡潔的形式：

```
∂ log π(a) / ∂z_i  =  𝟙[i == a] − π_i
```

乘上 advantage：

- advantage > 0 → 被選中的動作往上推，其他往下壓
- advantage < 0 → 整個翻轉

**梯度總和恆為 0**——因為機率總和固定是 1，推高一個必然壓低其他。

## 第一次的結果：訓起來了，但學到的東西不對

| | 正確率 | 平均獎勵 |
|---|---|---|
| 隨機策略 | 17.9% | −0.701 |
| 訓練後 | 85.9% | +0.374 |
| 完美策略（上限） | 100% | +0.603 |

85.9% 看起來不錯。**但拆開看就不是了：**

| 情況 | 正確率 |
|---|---|
| 該抽牌時 | **100%** |
| 該出牌時 | **54.9%** |
| 其中「有牌可出卻抽牌」 | 45.1% |

**它學會的是「不確定就抽牌」。**

### 為什麼

兩個原因疊在一起：

**一、分類不平衡。** 環境中 68.8% 的情況是「該抽牌」。
一個只會抽牌的 agent，整體正確率就有 68.8%。

**二、獎勵設計讓保守變成理性選擇。**

| 動作 | 獎勵 |
|---|---|
| 出對牌 | +1.0 |
| 出錯牌 | −1.0 |
| 該抽時抽 | +0.5 |
| **該出卻抽** | **−1.0** |

出錯牌與該出卻抽，罰得一樣重。所以在還沒學會「哪張接得上」之前：

```
不確定時出牌：可能 +1，可能 −1
不確定時抽牌：可能 +0.5，可能 −1
```

**下檔一樣，抽牌的上檔低但機率高**——保守是理性的。

> 這跟 lii 的三級介入是同一個問題結構：紅燈只佔少數，
> 一個「一律判綠燈」的系統準確率照樣很高，但毫無用處。

---

## 三種修法

| 代號 | 做法 | 想法 |
|---|---|---|
| **A** | 把「該出卻抽」的罰則從 −1 加重到 −2 | 讓保守不再是安全選擇 |
| **B** | 生成手牌時提高「接得上」的機率（30% 偏好） | 減少分類不平衡 |
| **C** | 加 entropy bonus（係數 0.02） | 鼓勵保持不確定，避免太早收斂 |

---

## 結果：單一種子 vs 五個種子

### 單一種子（seed = 20260818）

| 設定 | 該出牌時的正確率 |
|---|---|
| 基準 | 54.7% |
| A | 86.9% |
| B | 94.7% |
| C | 75.4% |
| **A+B** | **100.0%** |
| A+B+C | 87.0% |

看起來結論很清楚：A+B 完美，加上 C 反而變差。

### 五個種子（1, 42, 777, 20260818, 99999）

| 設定 | 平均 | 標準差 |
|---|---|---|
| 基準 | 59.0% | **24.8** |
| A | 76.9% | 9.5 |
| B | 81.4% | 11.1 |
| C | 63.6% | 12.9 |
| A+B | **95.2%** | 5.0 |
| A+B+C | 91.8% | **3.9** |

**三個只有多種子才看得到的事：**

**一、基準版本根本不穩定。** 標準差 24.8——一個種子跑出 100%，另一個只有 27.3%。
**如果只跑那個幸運的種子，會得出完全錯誤的結論。**

**二、A+B 的 100% 是運氣。** 五次平均 95.2%，最低 86.5%。

**三、C 的作用被誤判了。**

| | 平均 | 標準差 |
|---|---|---|
| A+B | 95.2% | 5.0 |
| A+B+C | 91.8% | **3.9** |

**entropy 讓平均降了 3.4 個百分點，但讓標準差從 5.0 降到 3.9。**

那是一個取捨（平均 vs 穩定），不是單純的好壞。
**單一種子的比較把它誤判成「有害」。**

## 這個實驗證明了什麼、沒證明什麼

### 證明了

- Actor-Critic 能學會拉密的一個子問題
- 手刻的前向／反向傳播是正確的（梯度與數值微分吻合到 1e-11）
- 獎勵設計與分類不平衡會讓 agent 學到「表面正確但實質無用」的策略
- **單一種子的實驗結論可能是錯的**

### 沒有證明

- **不是「AI 學會打拉密」。** 完整拉密的動作空間有數萬種，
  需要處理變長狀態表示與稀疏獎勵，超出這個階段的範圍。
- 狀態表示裡「接不接得上」的旗標是直接餵給網路的。
  真正的挑戰是讓網路自己學出那個關係，這裡繞過了。
- 五個種子仍然偏少。正式的 RL 論文通常跑 10 到 30 個種子。
- 環境是我自己寫的，它的難度分布也是我設計的參數決定的。

## 與教練系統的關聯

這個實驗跟 `coach/` 那套教練引擎不是同一個東西，但它們回答的是同一個問題的兩面：

| | 誰在學 | 訊號來源 |
|---|---|---|
| Actor-Critic | AI | Critic 估計的基準線 |
| 教練引擎 | 人 | 引導強度依關卡遞減 |

**兩者都在處理「什麼時候該給訊號、給多強」。**

一個未做的方向是把兩者接起來：用訓練好的 Actor 當「最佳解」的來源，
再用玩家表現與它的落差決定提示深度。那需要先解決完整拉密的訓練問題。

## 檔案

```
rl/
├── mini_env.h        簡化環境
├── actor_critic.h    手刻的 Actor 與 Critic（含反向傳播）
├── train.cpp         訓練主程式與評估
└── ablation.cpp      三種修法的對照實驗（含多種子驗證）
```

### 編譯

```bash
g++ -std=c++17 -O2 train.cpp -o train && ./train
g++ -std=c++17 -O2 ablation.cpp -o ablation && ./ablation
```

隨機種子固定，重跑會得到相同的數字。
